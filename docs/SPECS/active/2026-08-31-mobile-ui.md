# Mobile UI layer — shared core, dedicated mobile views (full parity)

Status: In progress
Owner: somesh   Date: 2026-08-31

## Problem

The responsive pass (spec 2026-08-31-mobile-responsive) made the desktop layout
survive a phone, but the phone UX is still desktop chrome squeezed narrow. Leading
photo apps (Google Photos, Immich, Ente) give phones a structurally different UX:
bottom tab bar, mobile grid, bottom-sheet actions, gesture-first lightbox.

## Decision

**One engine contract, two view layers.** Extract the pure logic of `app.js` into
`dist/core.js` (ES module; app.js is already `type="module"`, no bundler). Build a
new mobile frontend — `dist/mobile.html`, `dist/mobile.css`, `dist/mobile.js` — with
its own DOM designed for thumbs. The bridge serves the mobile page to phones
automatically (User-Agent contains `Mobile`; `?full=1` is the way back to the
desktop view). Desktop never imports the mobile files and renders unchanged.

Why not the alternatives: deeper responsive-in-place means a 5,400-line app.js grows
`if (mobile)` branches through every surface and the desktop DOM carries all mobile
chrome; a fully separate app duplicates the engine contract (68 commands, events,
query grammar, grid math) and drifts — the one-engine rule exists to prevent that.

User decisions (2026-08-31): shared core + mobile views · tabs **Photos · Search ·
People · Library**. Full parity remains the destination, delivered as working slices;
it is not a condition for the first mobile view to ship.

## Sequenced specs

### Spec A — shared core + bridge routing (foundation)

1. `dist/core.js`: pure logic extracted from app.js — `hydrate`, `justify`,
   `computeLayout` (parameterised to return the layout; desktop keeps a 2-line
   wrapper), `sectionFor(p, base)`, `parseQuery`/`matchesStructured`, `DAY`/`TIME`/
   `bytesLabel`/`monthKey`/`labelColour`, `inFolder`, `isRaw`/`needsConversion`,
   `project`/`unproject`, `straightenZoom`, `cosine`, the command-grammar text half
   (`VERBS`…`isCommand`), `loadGuard` factory (replaces `beginLoad`/`stillCurrent`).
2. `app.js` imports these; no behavior change.
3. Bridge (`remote.rs`): whitelist `mobile.*` and `core.js` in the embedded dist;
   `index_page_for(mobile)` serves the mobile page; shim injection understands the
   `<script src="mobile.js"` marker.
4. Parity test scans `mobile.js` invoke names too.
5. Gates: workspace tests, clippy `--all-targets -D warnings`, grammar test (it now
   evaluates core.js + app.js together), desktop screenshot regression.

### Spec B — mobile browser v1 (current slice)

Theme bootstrap + `[hidden]` contract replicated; state subset; loaders over the
existing `remote.js` shim; `progress`/`source-ready`/`library-changed` subscription.
Bottom tab bar with working Photos, Search, People and Library views. Virtualised
justified grid over core `computeLayout`, date headers, library/folder switching,
structured search and person filtering. Lightbox supports swipe navigation, pinch and
double-tap zoom, video playback, rating/label/info/rename, and delete-to-Trash. Every
write uses the existing engine command; source add/remove and irreversible Trash
emptying remain desktop-only in this slice.

### Spec C — deeper Search + People + Library workflows

Semantic search states and saved-search authoring; naming/merging/untagging people;
source depth and removal; Trash restore/empty workflows.

### Spec D — editing in the lightbox

Rotate/flip/straighten/crop/adjust as full-screen mobile editors; crop handles
touch-sized; Save keeps-original flow identical (same commands, same rekey rules).
Own spec so it can slip without holding back B/C.

### Spec E — duplicate review, organize, map, Ask

Dup review redesigned for swipes (full-screen pair compare, swipe = keep/next,
Reclaim Space); organize sheets; pinch-zoom map (Mercator math from core); Ask as a
sheet over any tab, same grammar, plan-cards before any write.

## Acceptance criteria (Spec B)

1. Rendered screenshots through the bridge at 390×844 of each surface, plus
   empty/offline states; 1440×900 desktop regression shot.
2. `node apps/desktop/tests/grammar.test.mjs`, workspace tests, clippy
   `--all-targets -D warnings` green; parity test covers both UIs.
3. No horizontal scroll at 390px; ≥40px touch targets.
4. Swipe, pinch and double-tap are covered by pointer/touch handling; real-device
   confirmation remains a release gate, not a claim from automated verification.

## Non-goals

No bundler, no framework, no native app, no offline mode, no second engine
contract. Desktop above the breakpoint stays as shipped.
